# 0004. API キーは承認済みスクリプトの中だけで使う

- 日付: 2026-10-03
- 状態: 採用

## 背景

API キーは `.env` に置いています。グローバルのフック（`~/.claude/hooks/block-dangerous.sh`）が、AI エージェントによる `.env` の読み取りを禁止しています。一方で、動画一覧の取得は AI エージェントに実行してほしいです。

## 決定

- API キーを使う処理は、ユーザーが承認したスクリプトの中にだけ書きます（今は `scripts/fetch-videos.sh` のみ）
- スクリプトは環境変数 `YOUTUBE_API_KEY` を使い、未設定なら `.env` から読み込みます
- キーは URL ではなく `X-Goog-Api-Key` ヘッダーで渡し、画面やログに出しません
- キーを扱うスクリプトを作成・変更するときは、毎回ユーザーの確認を取ります
- Google Cloud 側では、キーの API の制限を「YouTube Data API v3 のみ」にします。アプリケーションの制限は「なし」にします

## 理由

- フックの目的は「キーが AI の目に触れ、会話の記録に残ること」を防ぐことです。キーを出力しないスクリプト経由であれば、この目的は守られます
- ヘッダーで渡せば、エラー表示や URL のログにキーが混ざりません
- 家庭の回線は IP アドレスが変わるので、IP アドレスでの制限は使いにくいです。代わりに API の制限で、漏れたときの被害を「YouTube の公開情報を読むこと」だけに抑えます

## 影響

- フックはコマンドの文字列で判定しているので、スクリプト経由の読み取りは止められません。スクリプトの中身はユーザーの確認で守ります
- アプリ化するときは、アプリ専用のキーを別に作り、そのアプリからしか使えないよう制限を付けます

## 検討した他の案

- **ユーザーが毎回手で実行する**：一番安全ですが、手間がかかるため見送りました
- **フックに例外を追加する**：フックの設定が複雑になるため見送りました
- **シェルの環境変数にする**：キーがプロジェクトの外にも広がるため見送りました
